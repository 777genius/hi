Техническая памятка Senior Flutter. Это справочные знания, не подтверждение личного опыта. Используй только релевантные вопросу детали; не пересказывай памятку целиком и не увеличивай ответ без необходимости. Версионные API уточняй по версии проекта, не объявляй неподтверждённые версии актуальными.

Dart: final не означает deep immutability; const canonicalization относится к константным выражениям. Factory может вернуть существующий объект/subtype, не бывает async. Sealed ограничивает подтипы library; records имеют structural typing и value equality. Для пользовательских Unicode-символов используй characters.

Flutter: Widget — immutable конфигурация; Element — идентичность, зависимости и lifecycle; RenderObject — layout/paint/hit testing. BuildContext связан с Element. Constraints вниз, размеры вверх, положение задаёт родитель. Rebuild, relayout и repaint различаются. Совпадение runtimeType/key позволяет обновить Element. const не запрещает все rebuilds. ValueKey — стабильный ID, ObjectKey — identity, UniqueKey сбрасывает identity; GlobalKey поддерживает reparenting с издержками. Для перестановок lazy-list учитывай findChildIndexCallback.

Lifecycle: initState — создание ресурсов; didChangeDependencies — зависимости InheritedWidget; didUpdateWidget — смена конфигурации/подписок, build следует автоматически; deactivate временно, dispose окончательно. Освобождай controllers, subscriptions, timers, focus nodes. dispose не гарантируется при убийстве процесса. После await проверяй mounted/context.mounted, но отдельно защищайся от stale response через request generation или cancellation.

Bloc/Cubit: Bloc events обычно конкурентны. concurrent — перекрытие, sequential — очередь, droppable — пропуск новых пока занят, restartable — последний handler. Transformer действует в конкретном on<Event> bucket, не глобально. Отмена handler не гарантирует отмену HTTP/серверной операции. Cubit проще, но async methods тоже подвержены гонкам. Builder строит UI, Listener выполняет эффекты, Selector сужает rebuild. emit требует корректной value equality. Bloc не равен event sourcing.

Riverpod: watch подписывает, read читает однократно, listen выполняет реакцию, select сужает наблюдаемое значение. Provider/FutureProvider/StreamProvider — зависимости и read-only данные; Notifier/AsyncNotifier — изменяемое состояние. invalidate уничтожает прежнее состояние, не просто refresh HTTP. Учитывай autoDispose, recompute, onDispose, ref.mounted после await. Retry и pause/resume зависят от версии/настроек; денежные команды не должны автоматически повторяться как чтение данных. Не подменяй watch на read ради оптимизации.

Provider: scope и ownership зависимостей, create/dispose и .value для существующего экземпляра; watch/read/select имеют разные цели. MobX: observable, computed, action; Observer отслеживает чтения динамически. autorun сразу и при изменениях, reaction по выбранному выражению, when однократно по условию. Вызывай disposer, сужай Observer. Async actions не устраняют гонки и stale responses.

Async: код async до первого await выполняется синхронно. Microtasks выполняются перед следующим event; бесконечные microtasks вызывают starvation. await не блокирует поток, но CPU-работа в UI isolate блокирует кадры. Future.wait даёт конкурентное ожидание, не CPU-параллелизм; eagerError меняет момент ошибки, не отменяет работу. timeout не отменяет исходную операцию. unawaited не обрабатывает ошибки. Stream бывает single-subscription/broadcast; учитывай потерю событий, buffering/backpressure и lifecycle подписок.

Isolates: отдельная память и event loop; Isolate.run — разовая CPU-задача, spawn — долгоживущий worker; SendPort/ReceivePort — сообщения, TransferableTypedData — бинарные данные. Передача и запуск имеют overhead. compute на web не даёт отдельного isolate. I/O обычно не требует isolate.

Native: Channels/Pigeon для платформенных контрактов, EventChannel для событий с cleanup; FFI/JNI для подходящего низкоуровневого API после измерений. Не предполагай доступность произвольного Swift через C ABI. Потоки выполнения зависят от платформы/версии движка; UI операции соблюдают main-thread/MainActor constraints. Swift async не означает background; actor reentrant через await, перепроверяй инварианты; ARC допускает retain cycles, cancellation cooperative. Kotlin suspend сам не переключает поток; Main для UI, IO для blocking I/O, Default для CPU. Structured scopes/Job управляют lifecycle; StateFlow hot с текущим значением, SharedFlow broadcast, обычный Flow cold; collection привязывай к lifecycle.

Architecture: domain policies независимы от Flutter/HTTP/storage; repository скрывает источники данных, use case оправдан отдельной бизнес-операцией, Bloc/ViewModel координирует UI. Границы по фичам/доменам, явные зависимости, SOLID без интерфейсов для каждого trivial getter. Factory Dart не обязательно GoF Factory Method. Тестируй инварианты unit, UI widget, интеграции integration; mocks не доказывают реальную совместимость.

Performance: profile mode на реальном устройстве, отдельно UI/raster timing, CPU, retained memory. Бюджет кадра ~16.7 ms при 60 Hz и ~8.3 ms при 120 Hz. Lazy lists не делают network pagination. Сужай rebuild через selectors/const/малые поддеревья; decode изображений под нужный размер; TTL/invalidation/dedup кеша. RepaintBoundary ограничивает painting, не rebuild/layout, имеет стоимость. saveLayer, clipping, opacity, большие текстуры и overdraw могут перегрузить GPU. GC не убирает сохраняемые ссылки и native leaks.

Animations: implicit для простых переходов, AnimationController/Tween/CurvedAnimation для контроля; vsync/TickerMode и dispose обязательны. AnimatedBuilder.child сохраняет статическую часть; CustomPainter(repaint: animation) может repaint без build, shouldRepaint отражает изменения рисунка. Для Rive учитывай runtime, активные artboards, texture size и lifecycle; быстрый build не исключает raster/GPU bottleneck.

Мобильные платежи и сеть: сервер определяет статус платежа. Timeout после отправки означает unknown/pending: восстанавливай статус по operation ID, не повторяй списание вслепую. UI guard от double tap не заменяет server idempotency. Отмена запроса не отменяет операцию на сервере. После process death/3DS восстанавливай состояние с сервера. Биометрический boolean не доказательство серверной авторизации: подтверждение связывают с challenge и реквизитами. Keychain/Keystore для credentials; никаких server secrets в bundle и токенов/PII в логах. Обновление access token координируй одним refresh для конкурентных запросов, ограничивай повтор после 401. Для чтения — timeout, bounded retry/backoff/jitter, cancellation и защита от stale response. WebSocket — heartbeat/reconnect и восстановление пропущенных событий. Offline-first — локальный источник UI, очередь изменений, явное разрешение конфликтов и дедупликация синхронизации.

Flutter performance checklist: начать с воспроизведения на реальном устройстве в profile mode, записать baseline и сравнивать p50/p95/p99 frame times с бюджетом 16,7 мс при 60 Гц или 8,3 мс при 120 Гц. В DevTools Performance разделять UI и raster threads, выбирать медленные кадры и изучать timeline/CPU profiler; в Flutter Inspector использовать отслеживание rebuild и repaint rainbow как диагностику, не как цель оптимизации. Для GPU проверить offscreen layers/saveLayer, opacity, clip и изображения; для UI — build/layout, синхронный CPU, лишние rebuild и парсинг. Оптимизировать по измеренному узкому месту, повторять замеры на том же устройстве и проверять память в DevTools Memory и жизненный цикл ресурсов. Учитывать, что debug mode и эмулятор не отражают production performance, а Impeller и shader compilation зависят от версии и платформы.
